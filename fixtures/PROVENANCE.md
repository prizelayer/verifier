# Where `golden-vectors-v1.json` comes from

This file is **not written here**. It is generated from PrizeLayer's certified Kotlin draw engine
and committed to this repository unchanged, so that two independent implementations of the same
algorithm are judged against one artifact neither of them may edit.

| | |
|---|---|
| Source repository | `prizelayer/platform` (private) |
| Generated by | the `:fairness-vectors` Gradle module, `./gradlew regenerateFairnessVectors` |
| Source commit | `62a0b313af56bcc5ed06e71b444755838ef4eafd` (branch `kan-37-slot-mapping-vectors`) |

> **This commit is on an unmerged branch.** When it lands on `main`, this table must be updated to
> the merge commit. KAN-38 (S4) adds the automated two-way drift check that makes a stale copy here
> a red build in both repositories; until then the pin is maintained by hand.

## Why a copy rather than a submodule

`prizelayer/platform` is private and this repository is public, so public CI cannot fetch the file
at build time. Vendoring is forced by that asymmetry rather than chosen for convenience — and it
has a side benefit: this repository stays independently buildable by anyone, which is the whole
premise of a verifier that does not ask you to trust the thing it verifies.

## The anti-tamper rule

Neither implementation may edit this file to make itself pass. On the platform side a test
regenerates the fixture in memory and asserts byte-identity with the committed bytes, so a
hand-edit reddens the build at the moment it is introduced. On this side, the vectors are the
expectations — editing one to fix a failing test would be editing away the evidence.

If a vector here genuinely disagrees with this library, the correct outcome is a red build and a
conversation, not a smaller number.

## Format notes that bite

- **Every `i64` cents field is a decimal STRING**, never a JSON number. Signed 64-bit values exceed
  `Number.MAX_SAFE_INTEGER`, and `JSON.parse` rounds them before any code can intervene. Parse them
  with `BigInt` — `parseEdition()` in this library does.
- `u32` fields (`probabilityPpm`, `slotIndex`, `engineVersion`, `nonce`, `offset`, `chunk`) stay
  JSON numbers; they cannot overflow.
- `slotsAsGiven` arrays are deliberately **not** in ascending order. Caller order is never trusted
  by either implementation, and a vector that arrived pre-sorted would not test that.
- The `negative-cents` edition vector carries `"domainValid": false`. It exists to pin two's
  complement encoding, not to describe a legal edition — do not read it as a sanctioned config.
- The `attempt >= 1` branch of the derivation loop has **no vector and can never have one**
  (probability ≈6.6e-30). Its absence is a property of the algorithm, not a gap in coverage.
